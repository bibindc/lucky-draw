# Deploying Lucky Draw for free (Render + Neon)

This puts three things online, free:

| What | Where | Address (example) |
|---|---|---|
| Admin app + API | Render web service `lucky-draw-admin` | `https://lucky-draw-admin.onrender.com` |
| Public website | Render static site `lucky-draw-site` | `https://lucky-draw-site.onrender.com` |
| Database | Neon PostgreSQL | (private connection string) |

Free-plan limits worth knowing:
- The admin app/API **sleeps after 15 minutes without visitors**. The next visit wakes it in about a minute (the public site shows its loading dots, then fills in). See "Keeping it awake" below.
- Neon's free plan has 0.5 GB of storage — plenty for this app, including prize images (≤ 2 MB each).

You need: a GitHub account, about 30 minutes, and no credit card.

---

## 1. Put the code on GitHub (private)

1. Sign in at <https://github.com>, click **+** → **New repository**.
2. Name it `lucky-draw`, choose **Private**, and do **not** add a README, .gitignore or licence. Click **Create repository**.
3. In a terminal in the `lucky-draw` folder, run (replace `YOUR-USERNAME`):

   ```powershell
   git remote add origin https://github.com/YOUR-USERNAME/lucky-draw.git
   git push -u origin main
   ```

   Git asks you to sign in to GitHub the first time.

Your `.env` files, the local database and its backups are excluded by `.gitignore` and are never uploaded.

## 2. Create the database on Neon

1. Sign up at <https://neon.tech> (you can use "Continue with GitHub").
2. Create a project: name `lucky-draw`, latest PostgreSQL version, region **AWS Asia Pacific (Singapore)** (closest to Render's Singapore region and to India).
3. On the project dashboard click **Connect**. Make sure **Connection pooling is turned OFF** (the host name must *not* contain `-pooler`). Copy the connection string. It looks like:

   ```
   postgresql://neondb_owner:abc123@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

4. Add `&connect_timeout=15` to the end (it gives the database time to wake up):

   ```
   postgresql://neondb_owner:abc123@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&connect_timeout=15
   ```

   Keep this string private — it is the key to your data. You will paste it into Render twice.

## 3. Create both services on Render

1. Sign up at <https://render.com> with **GitHub**, and allow Render to see your `lucky-draw` repository.
2. Click **New** → **Blueprint**, pick the `lucky-draw` repository, and continue. Render reads `render.yaml` and lists two services: `lucky-draw-admin` and `lucky-draw-site`.
3. Fill in the values Render asks for:

   | Setting | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 2.4 |
   | `DIRECT_URL` | the same Neon string |
   | `ADMIN_EMAIL` | the email you will sign in with |
   | `ADMIN_PASSWORD` | a strong password, **at least 12 characters** |
   | `VITE_SITE_URL` | `https://lucky-draw-site.onrender.com` |
   | `VITE_API_BASE_URL` (site) | `https://lucky-draw-admin.onrender.com/api/v1` |

   `JWT_SECRET` is generated by Render automatically.
4. Click **Apply**. The first build takes 5–10 minutes. The admin service's build also creates the database tables and your super admin account.

## 4. Check the real addresses

Render shows each service's address at the top of its page. If a name was taken, Render adds letters (e.g. `lucky-draw-admin-x1y2.onrender.com`). If either address differs from what you typed in step 3.3:

1. Open the service whose setting is wrong → **Environment**, correct `VITE_SITE_URL` (admin service) or `VITE_API_BASE_URL` (site), and save.
2. Click **Manual Deploy** → **Deploy latest commit**. These addresses are built into the pages, so a redeploy is needed after changing them.

## 5. First sign-in and set-up

1. Open the admin address and sign in with `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
2. Create the campaign, draws, prizes (with images) and agents, as you did locally.
3. Open **Public website**, choose the featured campaign, add your phone, WhatsApp, email and join note, and **Save**.
4. Open the public website address. It shows the campaign within a minute.

## 6. Quick checks after the first deploy

- [ ] Sign in, sign out, and sign in again.
- [ ] Add a participant, then search for them with different capital letters (e.g. `ASHA` finds "Asha").
- [ ] Record a payment; upload a prize image and see it on the Prizes screen and on the public site.
- [ ] As an agent, open the same participant in two tabs and submit the same payment request in both at once: one is accepted, the other says a request is already pending.
- [ ] On the public site: countdown, prizes, contact buttons (call, WhatsApp, email) work on your phone.

## Updating the live app

Push to GitHub and Render redeploys both services automatically:

```powershell
git add -A
git commit -m "Describe the change"
git push
```

If you change the database schema (`backend/prisma/schema.prisma`), also create the PostgreSQL migration before committing:

```powershell
npm run prisma:migrate --workspace backend          # local SQLite, as before
npm run postgres:migration --workspace backend -- describe_the_change
```

The test suite fails if you forget the second command. Render applies new migrations during the next deploy.

## Keeping it awake (optional)

To avoid the one-minute wake-up, a free uptime monitor can visit the app every 10 minutes:

1. Sign up at <https://uptimerobot.com> (free).
2. Add an **HTTP(s)** monitor for `https://YOUR-ADMIN-ADDRESS/api/v1/health` with a 10-minute interval.

One always-on free service fits within Render's 750 free hours per month.

## Backups

Neon keeps only a short restore history on the free plan. For data you cannot lose, export it regularly: in Neon, use **Backup & Restore** if available on your plan, or run `pg_dump` with the connection string from step 2.

## Troubleshooting

| Problem | What to do |
|---|---|
| Build fails at `prisma migrate deploy` | Check `DIRECT_URL` is the **direct** Neon string (no `-pooler`) with `sslmode=require`. |
| Build fails at the seed step | `ADMIN_PASSWORD` must be at least 12 characters. |
| Build fails at `postgres:check` | Run `npm run postgres:migration --workspace backend -- <name>` locally, commit and push. |
| Sign-in works but you are signed out at once | Open the admin app at its `onrender.com` address (not through another site), so the cookie stays on the same origin. |
| Public site says it could not load the draw details | Check the site's `VITE_API_BASE_URL` ends in `/api/v1` and points to the admin service, then redeploy the site. Or the API was asleep — press **Retry** after a minute. |
| "Open public website" goes to the wrong place | Fix `VITE_SITE_URL` on the admin service and redeploy it. |

Forgot the admin password? Change `ADMIN_PASSWORD` on the admin service in Render and redeploy; the build resets the account's password.
